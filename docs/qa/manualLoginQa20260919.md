# 1번 로그인·홈 라우팅 수동 QA — 2026-09-19

상태: **1번 로그인·홈 라우팅 완료 (2026-09-19)**. 사용자가 체크리스트 전체의 실제 화면 동작이 정상임을 확인했고 완료 처리를 요청했다. 아래 통과는 사용자 수동 QA 확인 결과이며 에이전트의 자동 브라우저 실행 결과로 표기하지 않는다. 식별코드는 문서에 저장하지 않는다.

## 시작 환경

- 프론트: http://localhost:3000/ (mock 꺼짐)
- 백엔드: http://localhost:8080
- DB: `127.0.0.1:15432/beyond_may_qa`, 컨테이너 `beyond-may-qa-postgres-1`
- 기존 [최초 준비 기록](localQaBaseline20260919.md)은 생성 당시 스냅샷이다. 기존 코스 1은 현재 `ONGOING`으로 변경되어 시작 전 검사에 사용하지 않는다.
- 매 계정 검사는 기존 시크릿 창을 모두 닫고 새 시크릿 창에서 시작하면 저장된 여행 일정과 로그인 상태를 분리할 수 있다. 다른 탭만 여는 것은 계정 분리가 아니다.
- 홈 메뉴에서 닉네임·식별코드를 입력한다. 신규 브라우저에서 로그인 폼이 바로 보이지 않으면 기존 사용자 로그인/여행 이어가기를 선택한다.
- 자동 라우팅 검사 시작 주소는 반드시 `/`이다. `/?home=1`은 명시적으로 홈에 머무르는 예외다. 홈 아이콘으로 돌아온 뒤에는 주소를 확인한다.

## 조회 실패·재시도 검사 (M12)

서버를 중지하지 않고 자신의 브라우저에서 해당 API 요청만 차단한다.

1. `Q919Before`로 로그인한 상태에서 `http://localhost:3000/?home=1`을 연다.
2. Chrome 개발자 도구(F12)의 명령 메뉴(Ctrl+Shift+P)에서 `Request conditions`를 찾아 연다. 버전에 따라 네트워크 요청 차단 패널 이름으로 표시될 수 있다.
3. `http://localhost:8080/api/v1/courses` 요청을 차단하는 규칙을 추가하고 차단을 활성화한다. 개발자 도구는 열어 둔다.
4. 주소를 `http://localhost:3000/`으로 바꿔 접속한다.
5. `/places`나 지도로 이동하지 않고 홈에 “여행 상태를 불러오지 못했어요. 다시 시도해 주세요.”와 “다시 시도” 버튼이 표시되는지 확인한다.
6. 차단을 유지한 채 “다시 시도”를 눌러도 홈과 오류 안내가 유지되는지 확인한다.
7. 차단 규칙을 비활성화한 뒤 **페이지를 새로고침하지 말고** “다시 시도”를 누른다. 코스 6의 시작 전 팝업이 다시 표시되어야 한다.
8. 같은 절차를 `http://localhost:8080/api/v1/explorations*` 차단으로 한 번 더 반복한다. 코스 조회만 성공하고 탐험 조회가 실패해도 빈 상태로 취급하면 안 된다.
9. 끝나면 추가한 차단 규칙을 제거한다.

Chrome의 요청 차단 설정과 패널 이름은 [공식 Request conditions 안내](https://developer.chrome.com/docs/devtools/request-conditions)를 따른다. 이 검사는 네트워크 실패 재현이며 HTTP 500 응답 자체를 재현한 것은 아니다. 401은 별도의 세션 만료·재로그인 동작이다.

## 결과 기록

위 표의 실제 결과를 `통과` / `실패` / `미실행`으로 채운다. 실패하면 아래 내용을 붙인다. 식별코드와 토큰은 기록하거나 캡처하지 않는다.

```text
검사 번호:
검사 시각:
닉네임 / 코스 ID:
새 시크릿 세션인지:
시작 URL:
누른 버튼:
기대 URL·화면:
실제 URL·화면:
스크린샷:
반복 재현 여부:
```

이번 준비는 로컬 QA 데이터를 추가하고 로그인·조회 API를 검증하는 작업이다. 앱 코드·운영 DB는 수정하지 않으며, 이 표의 화면 판정은 사용자가 직접 실행하고 정상이라고 확인한 결과를 반영했다. 1번 이외의 전체 QA·배포 승인을 의미하지 않는다.
## 준비 확인 결과

- 위 8개 계정의 실제 로그인 API 성공과 내 코스·시작 전·진행 중·완료 탐험 조회를 확인했다. 확인용 토큰은 로그아웃했으며 저장하지 않았다.
- 초안 계정 조회 순서는 코스 4 → 5다. 코스 4의 updatedAt이 5보다 최신이다.
- 코스 6 / 탐험 4는 BEFORE이며 Q919Before·Q919BJoin 두 사용자가 ACTIVE로 참여한다.
- Q919Empty에는 코스와 탐험 참여 기록이 없다.
- 기존 진행 중 코스 2와 완료 코스 3은 그대로 재활용했다. 기존 코스 1은 ONGOING 상태로 보존했다.
- 새 코스 4·5·6은 각각 장소 3개, 일정 2026-09-19다. 재활용 코스 2·3의 일정은 2026-09-20이다.
- 프론트 루트 HTTP 200, 백엔드 health UP을 확인했다.
